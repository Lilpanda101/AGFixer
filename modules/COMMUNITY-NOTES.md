# Основания изменений и разбор гайдов

Изучены разные инструкции и обсуждения из предоставленного Telegram HTML-экспорта,
а не только один гайд автора утилиты. Служебные сообщения, повторные публикации,
прикреплённые отчёты и ссылки не считаются независимыми подтверждениями.
Приведённые ссылки — ориентиры к сообщениям; приватный экспорт целиком не распространяется.
Скрипты и EXE из экспорта не запускались. Ключи из исходных инструкций в пакет не перенесены.

## Как это превратилось в функции

- Моя форма → «Помощь и проверка AGFixer → Диагностический ZIP» и support.json с ограниченным набором полей.
- Споры о переключателях → неизвестные поля не выдаются за false, сценарии не смешиваются.
- Разные порты/режимы → аудит владельца порта и TLS через фактический HTTP/SOCKS5-прокси.
- Zapret-списки → проверка границ домена, включений/исключений, IPSet, подтверждённой схемы Game Filter.
- Проблемы NRPT/hosts → целевой аудит без глобального удаления чужих правил.
- Working/ошибки модели → отдельные признаки сети, backend, аккаунта и квоты; без автоматического диагноза «VPN плохой».
- Чёрный экран → только обратимое перемещение GPUCache после закрытия приложения; переписка/профиль не стираются.
- Противоречивые результаты → десять отдельных сценариев с ограничениями и ссылками, не кнопка «применить все советы».

## Что сознательно НЕ добавлено

Нет отключения TLS-проверки, auto-approve действий агента, покупки/ротации аккаунтов,
автоматического downgrade, очистки всего профиля/AppData, удаления всех hosts/NRPT,
подстановки старых чужих IP, установки EXE из чата, curl|sh, публичного открытого прокси,
массового завершения процессов и автопубликации логов.

Положительный отзыв — свидетельство конкретного случая, не причинное доказательство.
Отрицательный тоже не делает метод бесполезным во всех сетях. Версии Unlocker/IDE, провайдер,
регион, состояние аккаунта и серверная нагрузка могут различаться. Перед изменением фиксируйте
исходную конфигурацию и проверяйте по одному изменению за раз.

## Дополнение: настройка своего VPN

Пользователь предоставил скриншот гайда Ousa с переключателями Unlocker для VPN.
Эта схема вынесена в отдельный VPN/TUN-гайд; свой HTTP/SOCKS-прокси — в другой.
Точная ссылка на сообщение со скриншотом не указана, поэтому она не выдумана.
Порты не зафиксированы, заявления о неизбежных DNS-утечках/HTTP 400 или медленных групповых
прокси не перенесены как универсальные факты. Вход, автопатч и TLS проверяются вручную
в Unlocker: AGFixer не применяет патч и не включает эти переключатели своим VPN-профилем.

## NickDevo: дополнение v6.7

Кроме README разобраны Python relay.py/patcher.py/start-relay.bat, Go stream.go/tunnel.go и вспомогательные BAT.
Это не полный аудит репозитория и не аудит готового AntigravityUnlocker.exe. Чужие скрипты/EXE не запускались и в пакет не входят.

Добавлены два отдельных сценария с атрибуцией NickDevo. Настройки «локальный прокси ВЫКЛ, встроенные выходы ВКЛ»
из альтернативного README не подменяют мой профиль Zapret и VPN. Вариант с отдельным релеем ещё одна самостоятельная схема.
Перенесены идеи наблюдения фактической цепочки и раздельных этапов проверки, но не само исполнение релея.

В просмотренном Python-коде Smart Egress включён по умолчанию и использует сторонние IP; в нашем ручном гайде указан --no-smart.
В Go-коде https-прокси не получает TLS-обёртку до CONNECT, а SOCKS-ответы читаются без полного разбора длины.
Патчер использует постоянную резервную копию main.js без проверки версии IDE; launcher завершает слушателей порта 10809.
Эти реализации не скопированы. Проверка AGFixer явно отклоняет HTTPS-прокси, не выключает сертификаты и не завершает чужие процессы.

Тезис о стандартном пределе HTTP/2 в 128 КиБ не принят. Релеи передают TLS-байты, не выделяют HTTP/2-запросы,
и считают накопленный объём соединения. Начальное окно 65 535 байт и WINDOW_UPDATE — механизм управления потоком,
не максимальная длина prompt. Micro-pacing может быть полезной экспериментальной гипотезой, но не доказанным универсальным исправлением.
Специальный pacing/бенчмарк большого запроса в AGFixer не добавлен: текущая проверка отправляет только рукопожатие.
